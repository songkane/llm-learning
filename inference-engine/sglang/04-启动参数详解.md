# 04 · 启动参数详解

> 本篇系统梳理 SGLang 的核心启动参数（`ServerArgs`），讲清每个参数的**意义、作用**，以及它在**哪个关键模块中生效**的细节。
>
> 定义文件：`python/sglang/srt/server_args.py`，`class ServerArgs`（第 412 行）。CLI 参数名由字段名自动派生（`tp_size` → `--tp-size`）。
>
> **代码版本**：`sgl-project/sglang` @ **tag `v0.5.16`**（2026-07-24 发布）。启动参数是**最容易随版本变动**的部分（新增/改名/改默认值），使用前请以 `python -m sglang.launch_server --help` 为准。详见 [00 篇 · 分析的代码库版本](./00-导读与索引.md)。

## 1. 模型加载类

| 参数 | 默认 | 作用 | 生效模块 |
|------|------|------|----------|
| `--model-path`（别名 `--model`） | 必填 | 模型权重路径（本地目录或 HF repo ID） | ModelRunner 加载 |
| `--tokenizer-path` | =model | 分词器路径 | TokenizerManager |
| `--load-format` | `auto` | 权重格式：auto/pt/safetensors/dummy/gguf/bitsandbytes… | ModelRunner |
| `--trust-remote-code` | False | 允许 Hub 上自定义模型代码 | 模型加载 |
| `--context-length` | None（用 config） | 模型最大上下文长度 | 影响 KV 池上界、max_prefill |
| `--served-model-name` | None | 覆盖 `/v1/models` 返回的模型名 | OpenAI API 层 |

> **`--context-length`**：设太大会占用更多 KV 显存预算；一般保持默认（读模型 config）。

## 2. 量化与数据类型

| 参数 | 默认 | 作用 |
|------|------|------|
| `--dtype` | `auto` | 权重/激活精度：auto/half/float16/bfloat16/float32 |
| `--quantization` | None | 量化方法（fp8、awq、gptq、bitsandbytes 等） |
| `--kv-cache-dtype` | `auto` | **KV cache 存储精度**：auto/fp8_e5m2/fp8_e4m3/bf16/nvfp4 |

> **`--kv-cache-dtype fp8_e5m2`**：把 KV cache 从 bf16 压到 fp8，**显存占用减半**，能容纳更长上下文/更大并发，代价是极小的精度损失。直接影响 `MHATokenToKVPool`/`MLATokenToKVPool` 的每槽字节数。

## 3. 内存与调度类（最需要调优）

| 参数 | 默认 | 作用 | 生效模块 |
|------|------|------|----------|
| `--mem-fraction-static` | None（自动） | **静态分配（权重+KV 池）占显存比例** | KV 池大小计算 |
| `--max-running-requests` | None | 最大并发运行请求数 | Scheduler 组批上限 |
| `--max-total-tokens` | None（自动） | KV 池最大 token 数（多用于调试） | 内存池 |
| `--chunked-prefill-size` | None | 分块 prefill 单块最大 token 数，-1 禁用 | PrefillAdder |
| `--max-prefill-tokens` | 16384 | 单个 prefill 批最大 token 数 | PrefillAdder |
| `--schedule-policy` | `fcfs` | 调度策略：lpm/random/fcfs/dfs-weight/lof/priority | SchedulePolicy |
| `--schedule-conservativeness` | 1.0 | 调度保守度，越大越保守 | Scheduler retract |
| `--page-size` | None | 一个 page 的 token 数 | RadixCache/KV 池 |
| `--disable-radix-cache` | False | **禁用前缀缓存** | RadixCache |
| `--disable-overlap-schedule` | False | 禁用 CPU/GPU 重叠调度 | Scheduler 主循环 |

### 关键参数深入

**`--mem-fraction-static`（最常调）**
- 决定分给「模型权重 + KV cache 池」的显存比例，剩余留给激活值、CUDA Graph 等。
- **OOM 时优先调小它**（如 0.9 → 0.8）；想容纳更大并发/更长上下文时在不 OOM 前提下调大。
- 它直接决定 KV 池能放多少 token（自动计算的 `max_total_tokens`）。

**`--chunked-prefill-size`（长 prompt 场景关键）**
- 把超长 prompt 的 prefill 拆成多块，每块最多这么多 token，分多轮做。
- 好处：避免一个超长 prefill 长时间独占 GPU、阻塞其他请求的 decode；也能与 decode 混批（产生 `MIXED` 模式）。
- 在 `PrefillAdder.add_one_req()`（`schedule_policy.py:887`）里生效。

**`--schedule-policy`**
- `fcfs`（先来先服务，默认）；`lpm`（Longest Prefix Match，优先让能命中最长前缀缓存的请求排一起，最大化 RadixCache 复用）；`priority`（按优先级）。
- 在 `SchedulePolicy`（`schedule_policy.py:163`）与 `CacheAwarePolicy`（第 147 行）里生效。

**`--schedule-conservativeness`**
- 越大越保守，减少 decode 阶段的抢占（retract）频率。**频繁看到 retract 日志时调大它**。在 `update_running_batch` 的 OOM 判断中影响 `new_token_ratio`。

## 4. 并行策略类（分布式拓扑）

| 参数 | 别名 | 默认 | 作用 |
|------|------|------|------|
| `--tp-size` | `--tensor-parallel-size` | 1 | 张量并行大小 |
| `--pp-size` | `--pipeline-parallel-size` | 1 | 流水线并行大小 |
| `--dp-size` | `--data-parallel-size` | 1 | 数据并行大小 |
| `--ep-size` | `--expert-parallel-size` | 1 | 专家并行大小（MoE） |
| `--nnodes` | | 1 | 节点总数（多机） |
| `--node-rank` | | 0 | 当前节点 rank（多机每台不同） |
| `--dist-init-addr` | `--nccl-init-addr` | None | 分布式初始化主控地址，如 `192.168.0.2:25000` |
| `--nccl-port` | | None（随机） | NCCL 端口 |
| `--enable-dp-attention` | | False | attention 用 DP、FFN 用 TP（要求 dp_size==tp_size） |

### 关系要点
- **总 GPU 数 ≈ `tp_size × pp_size × dp_size`**，跨 `nnodes` 台机器，每台由 `node_rank` 区分。
- 所有节点用同一个 `--dist-init-addr`（rank0/head 地址）做 rendezvous，通过 NCCL 建立通信。
- `--enable-dp-attention`：DeepSeek-V2/V3、Qwen MoE 等场景，attention 层数据并行、FFN/MoE 张量并行，缓解 attention 的通信瓶颈。

（详细部署见文档 05）

## 5. 内核后端类

| 参数 | 默认 | 作用 |
|------|------|------|
| `--attention-backend` | None（自动） | attention 内核后端：flashinfer/fa3/triton… |
| `--decode-attention-backend` | None | **decode 专用**后端（优先级高于上者） |
| `--prefill-attention-backend` | None | **prefill 专用**后端（优先级高于 attention-backend） |
| `--sampling-backend` | None | 采样内核后端 |
| `--grammar-backend` | None | 约束解码（JSON/正则）后端 |

> **优先级**：`decode-attention-backend` / `prefill-attention-backend` > `attention-backend`。在 `ModelRunner.init_attention_backends()`（`model_runner.py:819`）里解析生效。允许 prefill 和 decode 用不同的最优 kernel。

## 6. 投机解码类（Speculative Decoding）

| 参数 | 默认 | 作用 |
|------|------|------|
| `--speculative-algorithm` | None | 算法：EAGLE/EAGLE3/NEXTN/NGRAM/STANDALONE… |
| `--speculative-draft-model-path` | None | 草稿（draft）模型路径 |
| `--speculative-num-steps` | None | 从 draft 模型采样的步数 |
| `--speculative-eagle-topk` | None | EAGLE2 每步采样 token 数 |
| `--speculative-num-draft-tokens` | None | draft 采样的 token 数 |

> 投机解码：用小 draft 模型一次猜多个 token，再用大 target 模型一次性验证（`TARGET_VERIFY` 模式），验证通过的直接采纳，从而**一次前向产出多个 token**，降低延迟。实现见 `python/sglang/srt/speculative/`。

## 7. 专家并行类（MoE）

| 参数 | 默认 | 作用 |
|------|------|------|
| `--ep-size` | 1 | 专家并行大小 |
| `--moe-a2a-backend` | `none` | MoE All-to-All 后端：none/deepep/mooncake/nixl/flashinfer… |

> MoE 模型（如 DeepSeek-V3、Mixtral）的专家分布到不同 GPU，token 通过 All-to-All 通信路由到对应专家。`--ep-size` 控制专家切分，`--moe-a2a-backend` 选择 all-to-all 通信实现。

## 8. PD 分离类（Prefill-Decode Disaggregation）

| 参数 | 默认 | 作用 |
|------|------|------|
| `--disaggregation-mode` | `null` | **一个开关切换整机角色**：null（不分离）/prefill（仅 prefill）/decode（仅 decode） |
| `--disaggregation-transfer-backend` | `mooncake` | KV 传输后端：mooncake/nixl/mori/ascend/fake |
| `--disaggregation-bootstrap-port` | 8998 | prefill 端 bootstrap 握手端口 |
| `--disaggregation-ib-device` | None（自动） | InfiniBand 设备（支持单设备/列表/每 GPU JSON） |
| `--num-reserved-decode-tokens` | 512 | 新请求进 running batch 时预留的 decode token 内存 |

> `--disaggregation-mode` 驱动 `DisaggregationMode` 枚举（`disaggregation/utils.py`），决定 Scheduler 创建哪些队列、跑哪个事件循环。（详见文档 05）

## 10. 参数间关系总结（调优心法）

```
【显存三件套】
  --mem-fraction-static  →  决定 KV 池大小  →  自动算出 max-total-tokens
       ↑ OOM 优先调小              ↓
  --chunked-prefill-size / --max-prefill-tokens  控制单批 prefill 规模

【调度】
  --schedule-policy (fcfs/lpm)   +   --schedule-conservativeness (retract 频繁时调大)
       ↓ lpm 最大化                        ↓
  --disable-radix-cache 关闭前缀缓存

【attention 后端优先级】
  --decode-attention-backend / --prefill-attention-backend  >  --attention-backend

【并行组合】
  总GPU ≈ tp_size × pp_size × dp_size （跨 nnodes 台，node_rank 区分，dist_init_addr 汇合）
  MoE: --ep-size + --moe-a2a-backend
  DP attention: --enable-dp-attention (需 dp_size==tp_size)

【PD 分离】
  --disaggregation-mode (prefill/decode) + --disaggregation-transfer-backend (mooncake)
```

**常见调优场景**：
- **OOM**：调小 `--mem-fraction-static`；或用 `--kv-cache-dtype fp8_e5m2` 压 KV。
- **长 prompt 卡顿**：设 `--chunked-prefill-size 2048` 之类拆块。
- **多轮/多分支复用高**：用 `--schedule-policy lpm` 最大化前缀缓存命中。
- **retract 日志频繁**：调大 `--schedule-conservativeness`。
